# 完了条件の定義 (Definition of Done)

> 「作業が完了した」と判断するための基準。  
> これを満たさない限り完了とみなさない。

---

## 全作業共通の完了条件

- [ ] 指定されたファイルが作成・変更された
- [ ] 既存プロジェクト（`README.md`, `index.html`, `netlify.toml`）に変更を加えていない
- [ ] APIキーや `.env` を作成していない
- [ ] `next-actions.md` の該当作業のステータスを「完了」に更新した
- [ ] `work-report-template.md` で報告した
- [ ] `auditor-check.md` のチェックを通過した

---

## ファイル作成作業の完了条件

- [ ] 指定した全ファイルが存在する
- [ ] 各ファイルにすぐ使えるテンプレートが入っている（空ファイルでない）
- [ ] ファイル名が正しい（スペルミスなし）
- [ ] `creation-gate.md` のゲートを通過している

---

## 決定作業の完了条件

- [ ] `decision-log.md` に DEC-ID 付きで記録されている
- [ ] 採用しなかった案も記録されている
- [ ] 「見直し条件」が明記されている

---

## 設計作業の完了条件

- [ ] 「やること」と「やらないこと」が明示されている
- [ ] トレードオフが説明されている
- [ ] 実行者が理解できる粒度で書かれている

---

## 会議の完了条件

- [ ] 全議題について「決定 / 保留 / 却下」のいずれかになっている
- [ ] 「未決定のまま終わった議題」がない（あれば次回議題として記録）
- [ ] `meeting-log.md` に記録された
- [ ] `next-actions.md` が更新された

---

## 「完了」ではないもの

| 状態 | 完了か？ | 理由 |
|---|---|---|
| ファイルを作ったが中身が空 | No | テンプレートが入っていない |
| 動くが `work-report-template.md` を書いていない | No | 報告が完了条件に含まれる |
| 実装したが監査を通っていない | No | `auditor-check.md` が必要 |
| 「だいたいできた」 | No | チェックリストを全て埋める |

---

## 完了の宣言方法

作業完了時は以下を宣言する:

```
## 完了宣言
- 作業名: 
- 完了日時: YYYY-MM-DD HH:MM
- DoD通過: すべてのチェックボックスにチェック済み
- レポート: work-report-template.md 参照
```
