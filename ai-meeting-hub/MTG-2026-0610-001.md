## 3. 設計提案・選択肢

### A案: self-host MVP で完結（今日）

**メリット:**
- PR #3 がほぼ完成状態なので今日中に「完成」と言える
- Docker + FastAPI + Claude + scheduler の設計力が伝わる
- APIキー管理の問題が発生しない
- 転職面接で「自分の環境で動かしました」と説明可能

**デメリット:**
- live URL がないため、見せるにはスクリーンショットや動画が必要
- 評価者が自分で動かすには Docker 環境が必要

### B案: hosted Webアプリ化（次フェーズ）

**メリット:**
- live URL を履歴書・ポートフォリオに載せられる
- 評価者がすぐ触れる

**デメリット:**
- APIキー公開問題（X API + Anthropic API の費用が誰でも使えてしまう）
- 認証・ユーザー分離設計が別途必要
- 今日中に完成しない
- `stock-ir-dashboard` 本体への影響リスクがある

---

## 4. 議論・対立点

| 論点 | A案（self-host） | B案（hosted） | 結論 |
|---|---|---|---|
| 完成速度 | 今日中 | 数日〜1週間 | A案有利 |
| ポートフォリオ訴求力 | スクショ必要 | live URL で強い | B案有利 |
| APIキーリスク | なし | 要設計 | A案有利 |
| 既存プロジェクトへの影響 | なし | リスクあり | A案有利 |
